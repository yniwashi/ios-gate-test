# DHP CPD testing in Gate Test

Updated: 2026-09-27 +03

The Gate Test app serves `helpers/cpd_opportunities.json` from its own static origin. Its CPD screen does not read the live API while running on the Gate Test domain or the local role-test server. This keeps the 2026–2027 draft separate from live R2 data. The Backend's `cpd-opportunities` app-data route and local R2 source are prepared but not deployed.

Open the Gate Test app as Ambulance Staff and choose **CPD** under Operations, below Websites and beside Shift Schedule. Check the Upcoming and Past Events tabs, text search, date and date-range search, Category 1 and 3 filters, format and provider filters, session details, source links, and registration states. The current helper has no Category 2 records, so the Category 2 filter should show an empty state. Other User access should not expose the tool.

This CPD view is for HMC staff. Staff-only activities from other providers are excluded from the list and provider filter. HMC staff-only activities remain eligible; when any are present, a **Show HMC staff-only events** filter appears. The current helper has no HMC staff-only activity, so that filter is hidden for now. Public activities from other providers remain visible.

The heading derives the coverage years and updated date from the helper. The updated label and date pill sit beside coverage. The intro tip explains how to return after opening a CPD link in the Ambulance App and mentions copying a link for another browser. Search and filters start collapsed, show an active-filter count, and can be expanded; date inputs are stacked with clear separation. Cards are grouped by activity and ordered by the nearest upcoming date or latest past date. Trailing year ranges such as `2026/2027` and `2026–2027` are removed from displayed activity titles; the JSON retains the original title. Provider names are prominent, and cards have a light border and shadow. Each summary value has a label above it; credits read as, for example, **Category 1 / 1 CPD point**. Summary badges use three equal columns; when a row has one remaining badge it fills the row, and when it has two they split the row. The date badge shows only the session start date. Multi-day sessions also show an inclusive calendar-day Duration badge; the date list or single-session Details shows the full range. Unknown prices are omitted from summaries. Distinct paid and free options appear as separately labeled badges, such as **Full series / 250 QAR** and **AZF employee / Free**. Multiple paid rates of the same currency use a compact price range. When three or more rates include both free and paid options, the card separates the paid price/range from a **Free option / Free** badge; the full eligibility and price options remain in Details. The full-width, light-colored View details control contains the date count for recurring activities and changes to Hide details when open.

For a recurring activity, Details lists all matching available or past dates at once. If a session's time, venue, format, duration, or credits differ, that fact appears beside its date. Shared details and activity-level links appear once. Pressing **Register for activity**, **Verify activity**, or **Provider** opens a styled dialog with **Copy link**, **Open inside Ambulance App**, and **Cancel** actions. Opening uses the same Web Clip behavior as the Websites tool; copying uses the clipboard with a local-browser fallback. The text search matches title, provider, DHP code, public note, and venue. A single entered date matches sessions covering that day; From and To dates together match sessions overlapping the inclusive range. The visible date list reflects the matching sessions. An invalid range shows a clear error, and **Clear search** resets text and dates. Only one activity card remains expanded at a time. The helper has no dedicated target-audience field; the Audience row shows only eligibility groups explicitly marked `yes`. Unknown or unavailable detail fields are hidden rather than showing `--`. If a future helper adds a full target-audience field, review this display before treating the Audience row as complete.

Local Staff and Other User sessions can be tested with the role-test server documented in `D:\Programming\iOS\Local Test Tools\README.md`. The CPD module uses the test helper on port 3000, including when accessed from an iPhone through the PC's LAN address. The live Gate Test Web Clip receives changes only when the separate Gate Test repository is published with user authorization.

Before copying any approved CPD code to the production iOS source, verify the production host resolves the shared API URL and do not copy this test-only JSON helper. See the Backend `Docs/CPD/Implementation.md` for the release order and source ownership.
